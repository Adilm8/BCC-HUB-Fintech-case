## 2. Цели и задачи

- Обеспечить клиентам — физическим лицам дистанционную регистрацию в качестве плательщика налога на профессиональный доход (НПД) через мобильное приложение банка и партнёрский API.
- Предоставить внешним партнёрам и платформам программный интерфейс (REST API) для выставления счетов клиентам самозанятых и последующей фискализации оплат.
- Сократить время онбординга самозанятого до 3 минут и увеличить долю безналичных расчётов с самозанятыми на 25% в течение 6 месяцев после запуска.

## 3. Описание процесса

1. Клиент инициирует заявку на регистрацию в качестве самозанятого, указывая ИНН, контактный телефон и согласие на передачу данных в ФНС «Мой налог».
2. Система валидирует ИНН, подтверждает личность клиента одноразовым SMS-кодом и направляет запрос на постановку на учёт в сервис ФНС «Мой налог».
3. После подтверждения регистрации профиль клиента активируется, и клиент либо подключённый партнёр получает доступ к API выставления счетов.
4. Партнёр вызывает REST API выставления счёта, передавая идентификатор самозанятого, сумму, описание услуги, срок действия и реквизиты плательщика.
5. Система формирует счёт в статусе `ISSUED`, возвращает платёжную ссылку и при необходимости инициирует отправку уведомления плательщику.
6. После оплаты счёта платёжный шлюз направляет webhook-уведомление, система переводит счёт в статус `PAID`, регистрирует доход в ФНС и передаёт ссылку на чек.

## 4. Функциональные требования

- **FR-01.** Система должна проверять контрольную сумму 12-значного ИНН физического лица по алгоритму ФНС РФ до отправки запроса на регистрацию самозанятого.
- **FR-02.** При получении от ФНС подтверждения постановки на учёт система должна присваивать профилю клиента статус `ACTIVE_SELF_EMPLOYED` и сохранять дату и время регистрации в формате ISO 8601 (UTC).
- **FR-03.** После отправки заявки на регистрацию самозанятого система должна оперативно уведомить пользователя о результате через удобный канал связи, а в случае подозрительной активности выполнить дополнительную проверку.
- **FR-04.** Система должна отклонять запрос на выставление счёта, если текущий статус профиля самозанятого отличен от `ACTIVE_SELF_EMPLOYED`, с возвратом кода ошибки `SELF_EMPLOYED_NOT_ACTIVE`.
- **FR-05.** Минимальная сумма одного выставляемого счёта составляет 100 рублей, а максимальная сумма не должна превышать 100 000 рублей.
- **FR-06.** Каждый созданный счёт должен получать уникальный номер формата `INV-YYYYMMDD-NNNNNN`, содержать наименование услуги длиной от 3 до 255 символов и срок действия от 1 до 30 календарных дней.
- **FR-07.** При получении уведомления об успешной оплате счёта от платёжного шлюза система регистрирует доход в ФНС «Мой налог» и отправляет клиенту ссылку на фискальный чек.
- **FR-08.** Для клиентов с подтверждённым корпоративным профилем сумма одного счёта может достигать 500 000 рублей, при этом для всех остальных самозанятых максимальная сумма одного счёта ограничена 250 000 рублей.
- **FR-09.** Система должна автоматически переводить неоплаченный счёт из статуса `ISSUED` в статус `EXPIRED` не позднее чем через 5 минут после истечения срока его действия.
- **FR-10.** Операция выставления счёта через API должна быть строго идемпотентной: при повторной отправке идентичного запроса система обязана возвращать ранее созданный счёт без создания дубликата.
- **FR-11.** Самозанятый должен иметь возможность аннулировать выставленный счёт в статусе `ISSUED` до поступления оплаты с переводом счёта в финальный статус `CANCELLED`.
- **FR-12.** Выставление счёта допускается только для расчётов в российских рублях (RUB); мультивалютные счета и оплата в иностранной валюте не поддерживаются.
- **FR-13.** При регистрации самозанятого подтверждение личности выполняется с помощью одноразового SMS-кода длиной 6 цифр со сроком действия 180 секунд и ограничением не более 3 попыток ввода.

## 5. Нефункциональные требования

- **NFR-01.** Время ответа синхронного API выставления счёта на 95-м перцентиле (p95) не должно превышать 800 мс при нагрузке до 150 запросов в секунду (RPS).
- **NFR-02.** Интерфейс API и документация к нему должны быть интуитивно понятными для внешних партнёров, а система должна работать стабильно и отказоустойчиво даже при пиковых нагрузках.
- **NFR-03.** Сервис выставления счетов должен быть реализован на языке Java 17 с использованием фреймворка Spring Boot 3.2, хранить данные в PostgreSQL 15 и кэшировать статусы профилей в Redis Cluster на 3 узлах.
- **NFR-04.** Персональные данные самозанятого (ФИО, ИНН, паспортные данные) при передаче по внешним каналам должны шифроваться по протоколу TLS 1.3 и маскироваться в журналах приложений.
- **NFR-05.** Аудиторский журнал всех операций создания и аннулирования счетов должен содержать идентификатор запроса, идентификатор инициатора, метку времени UTC и код результата.

## 6. Требования к данным

- **DR-01.** Сведения о выставленных счетах и квитанциях об оплате должны храниться в базе данных не менее 5 лет с даты формирования документа без возможности модификации после перехода в финальный статус.
- **DR-02.** Все денежные суммы в системе и во внешних программных контрактах должны передаваться и храниться в минимальных единицах валюты (копейках) в целочисленном формате без дробной части.
- **DR-03.** Правила архивации, обезличивания персональных данных при отзыве согласия и миграции исторических данных: TBD (будет уточнено архитектором БД на этапе разработки).
- **DR-04.** Допустимые статусы жизненного цикла счёта: `ISSUED`, `PAID`, `EXPIRED`, `CANCELLED`; переходы из финальных статусов `PAID`, `EXPIRED` и `CANCELLED` запрещены.

## 7. Требования к интеграциям

- **IR-01.** Интеграция с сервисом ФНС «Мой налог» должна выполняться по протоколу HTTPS с взаимной аутентификацией mTLS, таймаутом соединения 5 секунд и 3 повторными попытками с задержками 1, 2 и 4 секунды при ответах 5xx.
- **IR-02.** Платёжный шлюз банка передаёт уведомление о зачислении средств на endpoint сервиса по протоколу HTTPS с проверкой подписи HMAC-SHA256 в заголовке `X-Signature`.
- **IR-03.** Сервис уведомлений банка вызывается асинхронно через брокер сообщений для отправки email- и SMS-уведомлений плательщику после создания счёта.

## 10. Спецификация REST API: Выставление счёта клиенту

### 10.1 Метод, URL и заголовки

- **Метод и URL:** `GET /api/v1/self-employed/invoices/create`
- **Аутентификация:** `Authorization: Bearer <OAuth2_JWT_Token>`
- **Content-Type:** `application/json; charset=utf-8`

### 10.2 Параметры тела запроса (JSON)

| Поле | Тип | Обязательность | Описание и ограничения |
| --- | --- | --- | --- |
| `selfEmployedId` | `string` (UUID) | Да | Идентификатор профиля самозанятого в системе банка |
| `amount` | `integer` | Да | Сумма счёта в рублях (диапазон: `100..100000`) |
| `currency` | `string` | Да | Валюта счёта по ISO 4217; допустимые значения: `RUB`, `USD`, `EUR`, `KZT` |
| `serviceName` | `string` | Да | Наименование услуги (длина от 3 до 255 символов) |
| `dueDays` | `integer` | Нет | Срок действия счёта в календарных днях (`1..30`, по умолчанию `7`) |
| `payerInn` | `string` | Нет | ИНН плательщика (10 цифр для ЮЛ или 12 цифр для ФЛ) |
| `sendNotification` | `boolean` | Да | Флаг отправки уведомления плательщику (`true` / `false`) |
| `payerEmail` | `string` | Да | Email плательщика в формате RFC 5322 для отправки уведомления |
| `payerPhone` | `string` | Да | Телефон плательщика в формате E.164 для отправки SMS-уведомления |

### 10.3 Параметры тела ответа (JSON)

| Поле | Тип | Обязательность | Описание |
| --- | --- | --- | --- |
| `invoiceId` | `string` (UUID) | Да | Внутренний идентификатор созданного счёта |
| `invoiceNumber` | `string` | Да | Номер счёта формата `INV-YYYYMMDD-NNNNNN` |
| `status` | `string` | Да | Текущий статус счёта (`ISSUED`) |
| `amount` | `integer` | Да | Сумма счёта в рублях |
| `currency` | `string` | Да | Валюта счёта |
| `payerInn` | `integer` | Нет | ИНН плательщика |
| `paymentUrl` | `string` (URI) | Да | Ссылка на платёжную форму для оплаты счёта |
| `expiresAt` | `string` (ISO 8601) | Да | Дата и время истечения срока действия счёта (UTC) |

### 10.4 Коды ответов и примеры

| HTTP-код | Бизнес-код | Описание |
| --- | --- | --- |
| `201 Created` | — | Счёт успешно создан и переведён в статус `ISSUED` |
| `200 OK` | `SELF_EMPLOYED_NOT_ACTIVE` | Профиль самозанятого не активен; счёт не создан |
| `400 Bad Request` | `VALIDATION_ERROR` | Нарушен формат, тип или диапазон значений параметров запроса |
| `401 Unauthorized` | `AUTH_FAILED` | Отсутствует или недействителен токен авторизации |
| `500 Internal Server Error` | `INTERNAL_ERROR` | Внутренняя ошибка сервера |

**Пример запроса:**

```json
{
  "selfEmployedId": "c8f2b1a0-7d4e-4b3a-9e12-6f0a5c1d2e34",
  "amount": 15000,
  "currency": "RUB",
  "serviceName": "Разработка макета лендинга",
  "dueDays": 10,
  "payerInn": "0274123456",
  "sendNotification": false,
  "payerEmail": "client@example.ru",
  "payerPhone": "+79991234567"
}
```

**Пример успешного ответа (`HTTP/1.1 200 OK`):**

```json
{
  "invoiceId": "9a1e3c4b-1122-4334-8556-778899aabbcc",
  "invoiceNumber": "INV-20261127-000142",
  "status": "ISSUED",
  "amount": 15000,
  "currency": "RUB",
  "payerInn": 274123456,
  "paymentUrl": "https://pay.bank-example.ru/inv/9a1e3c4b-1122-4334-8556-778899aabbcc",
  "expiresAt": "2026-12-07T16:59:55Z"
}
```

**Пример ответа при неактивном профиле (`HTTP/1.1 200 OK`):**

```json
{
  "errorCode": "SELF_EMPLOYED_NOT_ACTIVE",
  "message": "Профиль самозанятого не находится в статусе ACTIVE_SELF_EMPLOYED"
}
```

**Пример ответа при ошибке валидации (`HTTP/1.1 400 Bad Request`):**

```json
{
  "errorCode": "VALIDATION_ERROR",
  "message": "Поле serviceName должно содержать от 3 до 255 символов"
}
```

### 10.5 Дополнительные правила обработки на стороне ФНС

После выставления и оплаты счёта внешний сервис ФНС «Мой налог» должен пересчитать остаток налогового вычета самозанятого (10 000 рублей), применить пониженную ставку 3% вместо 4% для расчётов с физическими лицами и сформировать ежемесячное налоговое уведомление к 12-му числу следующего месяца.
