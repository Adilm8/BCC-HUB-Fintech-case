## 2. Цели и бизнес-контекст

Функциональность предназначена для предоставления держателям дебетовых карт банка возможности самостоятельно управлять лимитами на снятие наличных в банкоматах (ATM) за пределами Российской Федерации через мобильное приложение.

Ключевые цели внедрения:
- Снижение доли мошеннических операций по снятию наличных в зарубежных банкоматах за счёт гранулярного управления ограничениями.
- Сокращение обращений в контакт-центр по вопросам включения, отключения и временного повышения зарубежных лимитов на 35% в течение 6 месяцев после внедрения.
- Повышение прозрачности контроля карточных ограничений для клиентов сегментов Standard и Premium во время зарубежных поездок.

## 3. Описание бизнес-процесса

1. Держатель дебетовой карты проходит аутентификацию в мобильном приложении и открывает экран настроек выбранной карты.
2. Приложение запрашивает актуальные параметры зарубежных лимитов в сервисе управления лимитами и отображает их клиенту.
3. Клиент включает или отключает снятие наличных за рубежом, задаёт новое значение суточного и/или месячного лимита либо оформляет временное повышение лимита на период поездки.
4. Сервис управления лимитами валидирует статус карты, тарифный сегмент и введённые значения.
5. При изменении лимита в сторону увеличения или включении операций за рубежом инициируется подтверждение операции одноразовым паролем (OTP).
6. После подтверждения сервис передаёт обновлённые параметры в процессинг Way4 и фиксирует запись в журнале изменений.
7. Клиент получает уведомление о применении новых настроек, а обновлённые лимиты отображаются в интерфейсе карты.

## 4. Функциональные требования

- **FR-01**: Система должна позволять держателю дебетовой карты просматривать текущие суточный и месячный лимиты на снятие наличных в банкоматах за рубежом в разделе управления картой мобильного приложения.
- **FR-02**: Максимальный допустимый суточный лимит снятия наличных за рубежом для карт сегмента Premium составляет 500 000 RUB, для карт сегмента Standard — 150 000 RUB.
- **FR-03**: Минимальный суточный лимит снятия наличных за рубежом составляет 100 USD, а шаг изменения лимита равен 5 000 RUB; при этом система сравнивает заданный лимит с суточной суммой снятий напрямую без указания валюты расчёта и курса конвертации.
- **FR-04**: После подтверждения нового значения лимита система должна оперативно обновить правила авторизации и при необходимости пересчитать доступный остаток по усмотрению процессинга.
- **FR-05**: Суммарный месячный лимит снятия наличных за рубежом не может быть меньше текущего суточного лимита.
- **FR-06**: При изменении параметров через ДБО суточный лимит для карт сегмента Premium не может превышать 300 000 RUB, при этом иных каналов управления лимитом не предусмотрено.
- **FR-07**: При увеличении зарубежного лимита система отправляет OTP-код по SMS через сервис нотификаций и после ввода кода сохраняет лимит в процессинге Way4.
- **FR-08**: Клиент вправе установить временное повышение зарубежного лимита на срок от 1 до 30 календарных дней с автоматическим возвратом к постоянному значению.
- **FR-09**: Для карт сегмента Standard суточный лимит снятия наличных за рубежом по умолчанию после выпуска карты равен 0 RUB (операции снятия наличных за рубежом запрещены до явного включения клиентом).
- **FR-10**: Для карт в статусе «Заблокирована» или «Просрочена» изменение зарубежных лимитов должно быть запрещено.
- **FR-11**: Система должна рассчитывать комиссию за конвертацию валюты по тарифу, отправлять события аудита в SIEM и отображать обновлённый лимит в ежемесячной PDF-выписке.
- **FR-12**: После успешного изменения лимита система должна в течение 10 секунд отправить держателю карты push-уведомление с указанием нового значения лимита и даты вступления в силу.
- **FR-13**: По истечении срока действия временного повышенного лимита в 23:59:59 МСК последнего дня система должна автоматически восстановить ранее действовавший постоянный лимит.

## 5. Нефункциональные требования

- **NFR-01**: Время ответа REST API при чтении текущих зарубежных лимитов не должно превышать 300 мс для 95-го перцентиля при нагрузке до 200 RPS.
- **NFR-02**: Интерфейс управления лимитами должен работать быстро, стабильно и обеспечивать высокий уровень отказоустойчивости при пиковых нагрузках в сезон отпусков.
- **NFR-03**: Все запросы к сервису управления лимитами должны передаваться по протоколу TLS версии не ниже 1.2 с проверкой валидного JWT-токена клиента.
- **NFR-04**: Доступность сервиса управления зарубежными лимитами должна составлять не менее 99,95% в календарный месяц без учёта плановых регламентных окон.

## 6. Требования к данным

- **DR-01**: Каждая запись истории изменений лимита должна содержать идентификатор карты, старое значение, новое значение, код валюты ISO 4217, канал изменения и метку времени в формате UTC ISO 8601.
- **DR-02**: Журнал изменений зарубежных лимитов должен храниться в оперативном хранилище не менее 36 месяцев с даты совершения изменения.

## 7. Требования к интеграциям

- **IR-01**: При обращении к процессингу Way4 таймаут ожидания ответа на запрос изменения лимита должен составлять 5 секунд с выполнением не более 2 повторных попыток с интервалом 1 секунду.
- **IR-02**: Интеграция с процессингом Way4 при обновлении зарубежного лимита должна быть строго идемпотентной, чтобы исключить дублирование изменений при сетевых повторах.
- **IR-03**: Проверка статуса карты и принадлежности карты текущему клиенту в сервисе аутентификации должна выполняться синхронно до отправки запроса в процессинг.

## 10. Спецификация REST API: Изменение лимитов на снятие наличных за рубежом

### 10.1. Метод и URL

Метод предназначен для обновления параметров лимита снятия наличных в зарубежных банкоматах по конкретной карте клиента.

```http
GET /api/v1/cards/{cardId}/foreign-atm-limits/update
Authorization: Bearer <JWT>
Content-Type: application/json
```

### 10.2. Параметры запроса

| Параметр | Расположение | Тип | Обязательность | Диапазон / формат | Описание |
| :--- | :--- | :--- | :--- | :--- | :--- |
| cardId | path | string (UUID) | Да | RFC 4122 | Уникальный идентификатор карты |
| durationDays | query | integer | Нет | 1..90 | Срок действия временного лимита в календарных днях |
| isForeignAtmEnabled | body | boolean | Да | true / false | Флаг разрешения снятия наличных за рубежом |
| dailyLimitAmount | body | integer | Да | 1000..500000 | Суточный лимит снятия наличных |
| monthlyLimitAmount | body | integer | Да | 1000..1500000 | Месячный лимит снятия наличных |
| currency | body | string | Да | ISO 4217 (3 символа) | Валюта лимита |
| otpCode | body | string | Нет | 6 цифр (`^[0-9]{6}$`) | Код подтверждения операции |

### 10.3. Параметры ответа

| Поле | Тип | Обязательность | Описание |
| :--- | :--- | :--- | :--- |
| cardId | string (UUID) | Да | Идентификатор карты |
| isForeignAtmEnabled | boolean | Да | Признак активности операций за рубежом |
| dailyLimitAmount | string | Да | Текущий установленный суточный лимит в формате "150000.00" |
| monthlyLimitAmount | integer | Да | Текущий установленный месячный лимит |
| currency | string | Да | Код валюты по ISO 4217 |
| updatedAt | string | Да | Дата и время обновления в формате UTC ISO 8601 |

### 10.4. Коды ответов и примеры

| HTTP-код | Значение | Описание |
| :--- | :--- | :--- |
| 200 OK | Успешно | Параметры зарубежного лимита успешно обновлены |
| 400 Bad Request | Ошибка валидации | Некорректный формат параметров или выход значения за допустимый диапазон |
| 401 Unauthorized | Не авторизован | Отсутствует или недействителен JWT-токен |
| 404 Not Found | Не найдено | Карта с указанным `cardId` не найдена или не принадлежит клиенту |
| 409 Conflict | Конфликт состояния | Карта заблокирована или просрочена |

**Пример успешного ответа (`200 OK`):**

```json
{
  "cardId": "8f2a9c41-3d12-4b65-9e08-7c1b2a4d5f90",
  "isForeignAtmEnabled": true,
  "dailyLimitAmount": "150000.00",
  "monthlyLimitAmount": 600000,
  "currency": "RUB",
  "updatedAt": "2026-11-27T11:45:12Z"
}
```

**Пример ответа при превышении максимального лимита (`200 OK`):**

```json
{"status": "ERROR", "errorCode": "LIMIT_EXCEEDED", "message": "Превышен максимально допустимый лимит"}
```

**Пример ответа при отсутствии карты (`404 Not Found`):**

```json
{
  "errorCode": "CARD_NOT_FOUND",
  "message": "Карта не найдена"
}
```

### 10.5. Дополнительные правила обработки

После сохранения параметров в процессинге Way4 сервис API синхронно обращается к БД и пересчитывает категорию риска клиента в таблице af_client_risk_score БД Oracle системы Антифрод по формуле risk = base_score * 0.8 + geo_weight.
