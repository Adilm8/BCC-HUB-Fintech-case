## 2. Цели и бизнес-контекст

Внедрение функции самостоятельной временной заморозки и разблокировки банковской карты направлено на решение следующих бизнес-задач:

- Снизить объём обращений в контакт-центр по вопросам временной блокировки карт на 40% в течение 6 месяцев после промышленного запуска.
- Предоставить клиентам инструмент мгновенного ограничения операций по карте при подозрении на временную утерю без необходимости перевыпуска пластика.
- Повысить уровень сохранности клиентских средств за счёт сокращения времени реакции между обнаружением инцидента и блокировкой карты.

## 3. Описание процесса

1. Авторизованный клиент открывает экран детальной информации по выбранной карте в мобильном приложении и нажимает кнопку «Заморозить карту».
2. Клиент при необходимости выбирает срок автоматической разморозки, указывает причину заморозки и подтверждает выполнение операции.
3. Мобильное приложение передаёт запрос в BFF Card Service, который проверяет текущий статус карты и суточный лимит операций изменения статуса.
4. BFF Card Service направляет команду на изменение статуса в процессинговый центр Way4 и после получения ответа обновляет состояние карты на FROZEN.
5. Для снятия заморозки клиент нажимает кнопку «Разблокировать карту», вводит одноразовый код подтверждения SMS-OTP и после успешной проверки получает статус ACTIVE.
6. Система уведомлений отправляет клиенту push-уведомление о новом статусе карты, а событие фиксируется в журнале аудита.

## 4. Функциональные требования

**FR-01.** Временная заморозка доступна держателям активных (статус ACTIVE) дебетовых и кредитных карт физических лиц.

**FR-02.** В статусе FROZEN система отклоняет абсолютно все расходные операции по карте, включая POS-оплаты, онлайн-платежи, снятие наличных и ранее оформленные регулярные (рекуррентные) списания.

**FR-03.** В статусе FROZEN входящие переводы на карточный счёт, зачисления возвратов от мерчантов и погашение задолженности по кредитной карте выполняются без ограничений.

**FR-04.** Клиент может выполнять операции заморозки и разблокировки для одной карты суммарно не более 5 раз в течение скользящих 24 часов; на 6-й попытке система отклоняет запрос с сообщением о превышении суточного лимита.

**FR-05.** При активной временной заморозке карты ранее подключённые рекуррентные списания по подпискам (COF/MIT) и списания комиссий банка продолжают выполняться в штатном режиме.

**FR-06.** При заморозке клиент может задать срок автоматической разморозки карты в диапазоне от 1 до 30 календарных дней включительно; по истечении заданного срока карта автоматически переводится в статус ACTIVE.

**FR-07.** Разблокировка карты из статуса FROZEN в статус ACTIVE выполняется только после успешной проверки одноразового SMS-OTP кода, отправленного на доверенный номер телефона клиента.

**FR-08.** При выявлении подозрительной активности клиента система должна своевременно уведомить подразделение ИБ и при необходимости ограничить возможность самостоятельной разблокировки карты.

**FR-09.** При попытке расходной операции по замороженной карте на сумму свыше 50 000 RUB система формирует высокоприоритетное предупреждение для службы мониторинга мошенничества.

**FR-10.** Карты в статусах LOST, STOLEN, EXPIRED и CLOSED не подлежат временной заморозке через мобильное приложение; элемент управления заморозкой для них не отображается.

**FR-11.** В течение 10 секунд после смены статуса карты на FROZEN или ACTIVE система отправляет клиенту push-уведомление с последними 4 цифрами номера карты и новым статусом.

**FR-12.** При переходе карты в статус FROZEN приложение отображает иконку снежинки поверх миниатюры карты, а также сервис аналитики рассчитывает ежемесячную воронку конверсии заморозок и автоматически рассылает PDF-отчёт руководству каждую пятницу.

## 5. Нефункциональные требования

**NFR-01.** Функция заморозки и разблокировки карты должна работать максимально быстро, иметь интуитивно понятный интерфейс и обеспечивать высокую отказоустойчивость при пиковых нагрузках.

**NFR-02.** 95-й перцентиль (p95) времени обработки запроса на заморозку или разблокировку карты в BFF Card Service не должен превышать 1500 мс при нагрузке до 120 RPS.

**NFR-03.** Доступность сервиса управления статусом карты BFF Card Service должна составлять не менее 99,95% в календарный месяц без учёта плановых технологических окон.

**NFR-04.** Полный номер карты (PAN) и одноразовый код SMS-OTP запрещено записывать в текстовые журналы приложения, трассировки и тексты ошибок.

## 6. Требования к данным

**DR-01.** Каждая операция изменения статуса карты фиксируется в журнале аудита с полями: eventId, clientId, cardId, previousStatus, newStatus, initiatorChannel, timestampUtc и resultCode.

**DR-02.** Все метки времени в базе данных BFF Card Service и в интеграционных сообщениях хранятся и передаются в формате ISO-8601 в часовом поясе UTC.

**DR-03.** Сроки хранения записей журнала аудита, правила обезличивания персональных данных и политика архивирования: TBD (подлежит уточнению с подразделением ИБ).

## 7. Интеграционные требования

**IR-01.** Взаимодействие между мобильным приложением и BFF Card Service осуществляется по протоколу HTTPS (TLS 1.3) с обязательной передачей Bearer JWT-токена текущей сессии клиента.

**IR-02.** Для фактической смены статуса карты BFF Card Service отправляет синхронный запрос в процессинговый центр Way4, получает подтверждение успешной операции и обновляет локальный кэш статуса карты.

**IR-03.** Для проверки кода SMS-OTP при разблокировке карты BFF Card Service вызывает OTP Validation Service по gRPC с таймаутом 800 мс и не более 1 повторной попыткой при сетевой ошибке.

## 10. Спецификация REST API: Управление заморозкой карты

### 10.1. Метод и URL

- Метод и путь: `GET /api/v1/cards/{cardId}/freeze-status`
- Формат обмена: `application/json; charset=utf-8`
- Аутентификация: заголовок `Authorization: Bearer <JWT>`

### 10.2. Правила обработки и идемпотентность

Метод является строго идемпотентным: при повторной отправке запроса из-за сетевого таймаута гарантируется однократное изменение статуса карты без дублирования событий в процессинге и аудите.

В рамках обработки вызова данного API ядро процессинга Way4 обязано напрямую обновить флаг в таблице W4_CARD_LIMITS, пересчитать антифрод-скоринг в модуле AntiFraud Engine и поставить задачу в ночной регламентный батч сверки с МПС.

### 10.3. Параметры запроса

| Параметр | Расположение | Тип | Обязательность | Диапазон / Ограничения | Описание |
|---|---|---|---|---|---|
| Authorization | Header | string | Да | Bearer JWT | Токен текущей авторизованной сессии клиента |
| cardId | Path | string (UUID) | Да | RFC 4122 UUID | Идентификатор карты в BFF Card Service |
| action | Body | string (enum) | Да | FREEZE, UNFREEZE | Целевое действие со статусом карты |
| autoUnfreeze | Body | boolean | Да | true, false | Признак включения автоматической разморозки |
| unfreezeAfterDays | Body | integer | Нет | 1..90 | Срок авторазморозки в календарных днях (при autoUnfreeze = true) |
| useCustomReason | Body | boolean | Да | true, false | Признак указания пользовательской причины заморозки |
| customReasonText | Body | string | Да | 1..200 символов | Текст причины заморозки; не заполняется при useCustomReason = false |
| otpCode | Body | string | Условно | 6 цифр (000000..999999) | Код SMS-OTP; обязателен при action = UNFREEZE |

### 10.4. Параметры ответа (200 OK)

| Поле | Тип | Обязательность | Описание |
|---|---|---|---|
| cardId | integer (int64) | Да | Идентификатор карты |
| status | string (enum) | Да | Текущий статус карты (ACTIVE, FROZEN) |
| currency | string | Да | Валюта карточного счёта (KZT) |
| autoUnfreezeAt | string (ISO-8601) | Нет | Плановая дата и время автоматической разморозки в UTC |
| updatedAt | string (ISO-8601) | Да | Фактическое время обновления статуса карты в UTC |

### 10.5. Коды ответов и примеры

| HTTP-код | Значение | Описание |
|---|---|---|
| 200 OK | Успешно | Статус карты успешно изменён |
| 400 Bad Request | Ошибка валидации | Некорректный формат или значение входных параметров |
| 401 Unauthorized | Не авторизован | Отсутствует, повреждён или истёк JWT-токен |
| 409 Conflict | Конфликт состояния | Карта уже находится в целевом статусе или имеет статус LOST, STOLEN, EXPIRED, CLOSED |
| 429 Too Many Requests | Превышен лимит | Превышен суточный лимит операций заморозки/разблокировки |
| 500 Internal Server Error | Внутренняя ошибка | Внутренняя ошибка сервиса при обработке запроса |

**Пример 1. Успешная заморозка карты (HTTP/1.1 200 OK):**

```json
{
  "cardId": 984512034,
  "status": "FROZEN",
  "currency": "KZT",
  "autoUnfreezeAt": "2026-12-07T10:15:00Z",
  "updatedAt": "2026-11-27T10:15:00Z"
}
```

**Пример 2. Ошибка — карта уже заморожена (HTTP/1.1 200 OK):**

```json
{
  "errorCode": "CARD_ALREADY_FROZEN",
  "message": "Карта уже находится в статусе FROZEN"
}
```

**Пример 3. Ошибка — превышен суточный лимит (HTTP/1.1 429 Too Many Requests):**

```json
{
  "errorCode": "DAILY_LIMIT_EXCEEDED",
  "message": "Превышен суточный лимит операций заморозки и разблокировки карты"
}
