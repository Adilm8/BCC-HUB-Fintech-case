# Спецификация требований: отчёты по расчётам с мерчантами (эквайринг)

| Атрибут | Значение |
|---------|----------|
| Идентификатор документа | ACQ-SET-RPT-001 |
| Версия | 0.7 (на согласовании) |
| Владелец | Управление торгового эквайринга |
| Статус | Черновик |

## 1. Введение

### 1.1. Цель документа

Документ описывает требования к формированию и доставке отчётов по расчётам с торгово-сервисными предприятиями (мерчантами) по операциям эквайринга. Отчёт позволяет мерчанту сверить поступившую выручку, удержанную комиссию и возвраты.

### 1.2. Область применения

Документ распространяется на подсистему «Расчётные отчёты» в составе платформы торгового эквайринга и на её интеграцию с процессинговым центром, учётной системой Банка и каналами доставки мерчантам.

### 1.3. Определения

- Операционный день — календарные сутки, по итогам которых процессинг закрывает реестр операций.
- Реестр операций — файл со списком авторизованных и завершённых операций по терминалам мерчанта.
- Выручка к перечислению — сумма операций за вычетом комиссии, возвратов и чарджбэков.
- Рабочий день — день, не являющийся выходным или нерабочим праздничным днём по производственному календарю Российской Федерации.
- Договор эквайринга — соглашение между Банком и мерчантом о приёме платежей по банковским картам и порядке расчётов.
- Чарджбэк — опротестованная держателем карты операция, по которой платёжная система потребовала возврат средств.

## 2. Бизнес-требования

- BR-01. Мерчант должен получать ежедневный отчёт по расчётам за предыдущий операционный день по каждому своему договору эквайринга.
- BR-02. Отчёт о расчётах должен быть доступен мерчанту не позднее 09:00 по московскому времени следующего рабочего дня.
- BR-03. Банк должен перечислять выручку мерчанту на следующий рабочий день после операционного дня, то есть по схеме T+1.
- BR-04. Размер комиссии эквайринга указывается в отчёте в процентах от суммы операции, например 1,6%.
- BR-05. Чарджбэки должны включаться в отчёт отдельной строкой со знаком «минус» и ссылкой на исходную операцию.
- BR-06. Мерчант должен иметь возможность выгрузить отчёт за любой период в пределах последних 12 месяцев.
- BR-07. Мерчант должен получать сводный месячный отчёт для передачи в бухгалтерию.

## 3. Системные требования

### 3.1. Формирование отчёта

- SR-01. Система должна формировать отчёт по расчётам на основании реестра операций, полученного из процессингового центра после закрытия операционного дня.
- SR-02. Отчёт должен формироваться в форматах CSV и XLSX и содержать для каждой операции дату, время, номер терминала, маскированный номер карты, сумму, комиссию и сумму к перечислению.
- SR-03. Формирование отчётов по всем договорам эквайринга должно завершаться не позднее 12:00 по московскому времени рабочего дня, следующего за операционным.
- SR-04. Повторный запуск формирования отчёта за тот же операционный день не создаёт дубликатов отчёта.
- SR-05. Все суммы в отчёте должны указываться в российских рублях.
- SR-06. Возвраты и чарджбэки должны вычитаться из суммы продаж без отдельного отражения в отчёте.
- SR-07. Срок перечисления выручки мерчанту по результатам операционного дня составляет два рабочих дня (T+2).
- SR-08. Комиссия должна рассчитываться по каждой операции и округляться до копейки по правилам математического округления.

### 3.2. Доставка и доступ

- SR-09. Система должна формировать отчёт, сохранять его в архиве, отправлять мерчанту по электронной почте, публиковать в личном кабинете и обновлять сводную витрину управленческой отчётности.
- SR-10. Система должна своевременно уведомлять мерчанта о формировании отчёта.
- SR-11. Доступ к отчётам в личном кабинете должен предоставляться только после аутентификации пользователя с применением второго фактора.
- SR-12. Отчёт мерчанта должен быть доступен в личном кабинете только пользователям с ролью «Бухгалтер мерчанта» или «Администратор мерчанта».
- SR-13. Для мультивалютных договоров отчёт должен формироваться отдельно по каждой валюте расчётов.
- SR-14. Идентификатор мерчанта (MID) представляет собой 10-значное число и присваивается при заключении договора эквайринга.

- SR-15. Маскированный номер карты в отчёте должен содержать только первые 6 и последние 4 цифры номера, остальные цифры заменяются символом «*».
- SR-16. Каждая строка отчёта по операции должна содержать код авторизации операции, полученный от процессингового центра.

## 4. Нефункциональные требования

- NFR-01. Система должна обладать высокой надёжностью и обеспечивать удобство работы бухгалтеров мерчантов.
- NFR-02. Формирование отчёта по реестру в 10 миллионов операций должно занимать не более 1 секунды.
- NFR-03. Отклик на запрос реестра за один операционный день в личном кабинете не должен превышать 3 секунд для 95% запросов при объёме до 100 000 операций.
- NFR-04. Генерация отчётов должна выполняться на кластере Apache Spark, а промежуточные данные должны храниться в ClickHouse.
- NFR-05. Журнал доступа к отчётам должен храниться не менее 3 лет.
- NFR-06. Подсистема должна поддерживать горизонтальное масштабирование для обработки реестров мерчантов с объёмом более 1 миллиона операций за сутки.

## 5. Требования к интеграции

### 5.1. Каналы обмена

- INT-01. Реестр операций должен передаваться из процессингового центра в подсистему в виде файла по защищённому каналу SFTP с аутентификацией по ключу SSH.
- INT-02. Система должна размещать файл отчёта на SFTP-сервере мерчанта в каталоге, указанном в договоре эквайринга.
- INT-03. Имя файла отчёта должно иметь вид `settlement_{merchant_id}_{YYYYMMDD}.csv`.
- INT-04. Файл отчёта должен передаваться в кодировке UTF-8 с разделителем полей «точка с запятой».

### 5.2. Формат файла отчёта

| Поле | Тип | Описание |
|------|-----|----------|
| merchant_id | string | Идентификатор мерчанта в формате UUID |
| terminal_id | string | Номер терминала, до 8 символов |
| operation_date | string | Дата и время операции в формате ISO 8601 |
| gross_amount | number | Сумма операции, в тысячах рублей |
| commission_rate | number | Ставка комиссии в базисных пунктах, например 1.6 |
| commission_amount | number | Сумма удержанной комиссии, в рублях |
| net_amount | number | Сумма к перечислению, в рублях |
| operation_type | string | Тип операции: SALE, REFUND, CHARGEBACK |

### 5.3. Взаимодействие с учётной системой

- INT-05. Подсистема должна получать из учётной системы Банка подтверждения о фактическом перечислении выручки и сопоставлять их с отчётом по номеру платёжного поручения.
- INT-06. Расхождения между суммой к перечислению в отчёте и суммой фактического перечисления должны выделяться в отдельном разделе отчёта.

## 8. Допущения и ограничения

- Процессинговый центр передаёт реестр операций не позднее 04:00 по московскому времени.
- Список мерчантов и реквизиты договоров эквайринга предоставляет договорная система Банка.
- Требования к формату сводного месячного отчёта будут уточнены в версии 0.8.

## 9. Ответственные

- Владелец требований: руководитель направления торгового эквайринга.
- Системный аналитик: ведущий аналитик управления торгового эквайринга.
- Согласующие: департамент информационных технологий, управление информационной безопасности, бухгалтерия Банка.
