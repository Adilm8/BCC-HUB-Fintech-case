# API «Регулярное погашение кредита с карты» (loan-autopay), версия 1.2

## 1. Бизнес-контекст

Сервис позволяет заёмщику Банка поручить регулярное списание ежемесячного платежа по кредиту с банковской карты, чтобы не пропускать даты погашения. API используется мобильным приложением и интернет-банком.

Бизнес-правила сервиса:

- Для списания может использоваться только карта Банка, принадлежащая заёмщику по кредитному договору.
- День списания выбирается клиентом в диапазоне от 1 до 28 числа месяца, чтобы исключить проблему с короткими месяцами.
- Сумма списания равна сумме ближайшего платежа по графику погашения.
- Если списание не удалось, Банк выполняет не более трёх повторных попыток с интервалом 24 часа.
- Для создания правила требуется действующее согласие клиента, оформленное в приложении.

## 2. Общие положения

- Базовый адрес: `https://api.bank.example/loan-autopay/v1`.
- Все запросы должны содержать заголовок `Authorization: Bearer <access_token>`.
- Тело запросов и ответов передаётся в формате JSON в кодировке UTF-8.
- Все методы, изменяющие состояние, идемпотентны: повторный вызов с теми же данными не создаёт дубликатов.
- Все денежные суммы передаются в копейках целым числом (integer).
- Все даты и время передаются в формате ISO 8601 в часовом поясе UTC.
- Валюта всех операций — российский рубль (RUB).

## 3. Методы

### 3.1. Создание правила автоплатежа

`POST /loans/{loanId}/autopay`

Параметры пути:

| Параметр | Тип | Описание |
|----------|-----|----------|
| loanId | integer | Идентификатор кредитного договора |

Тело запроса:

| Поле | Тип | Обязательное | Описание |
|------|-----|--------------|----------|
| cardToken | string | да | Токен карты Банка, любой карты, в том числе карты третьего лица |
| paymentDay | integer | да | День месяца списания, от 1 до 31 |
| consentId | string | да | Идентификатор согласия клиента |
| paymentAmount | string | нет | Фиксированная сумма платежа в копейках |

Успешный ответ: `201 Created`.

Если правило автоплатежа по кредиту уже существует, метод возвращает код 400 и ошибку `AUTOPAY_ALREADY_EXISTS`.

Пример ответа:

```
HTTP/1.1 200 OK
{
  "autopayId": "b7c1e0f2-5a4d-4c36-9d3e-1f8a2b6c7d90",
  "loanId": "LN-2026-000145",
  "status": "ACTIVE",
  "paymentDay": 15,
  "paymentAmount": 45000.50,
  "nextPaymentDate": "2026-12-15T00:00:00Z"
}
```

### 3.2. Получение правила автоплатежа

`GET /loans/{loanId}/autopay`

Метод возвращает действующее правило автоплатежа по кредиту. Если кредит не найден, метод возвращает `404 Not Found` с кодом ошибки `LOAN_NOT_FOUND`.

Поле `status` принимает значения `ACTIVE`, `SUSPENDED` и `CANCELLED`.

### 3.3. Изменение правила автоплатежа

`PATCH /loans/{loanId}/autopay`

Метод обновляет только переданные в запросе поля: `cardToken`, `paymentDay` и `paymentAmount`. Непереданные поля сохраняют прежние значения.

### 3.4. Отключение автоплатежа

`DELETE /loans/{loanId}/autopay`

Метод отключает правило автоплатежа. В случае успеха возвращается `204 No Content` без тела ответа. Запланированные, но ещё не исполненные списания отменяются.

### 3.5. Приостановка автоплатежа

`GET /loans/{loanId}/autopay/suspend`

Метод переводит правило в состояние приостановки на срок, указанный в параметре `days`. После окончания срока правило автоматически возвращается в статус `ACTIVE`. Пока правило находится в статусе `PAUSED`, списания не выполняются.

### 3.6. История списаний

`GET /loans/{loanId}/payments`

Параметры запроса:

| Параметр | Тип | Описание |
|----------|-----|----------|
| fromDate | string | Начало периода, формат ISO 8601 |
| toDate | string | Конец периода, формат ISO 8601 |
| limit | integer | Количество записей на странице, от 1 до 100, по умолчанию 20 |
| cursor | string | Курсор следующей страницы из предыдущего ответа |

Метод возвращает список попыток списания с полями `attemptId`, `attemptDate`, `amount` и `result`.

### 3.7. Поиск карты клиента

`GET /cards/lookup?pan={pan}`

Метод возвращает токен карты по её полному номеру, переданному в параметре запроса `pan`.

### 3.8. Расчёт ближайшего платежа

`GET /loans/{loanId}/payments/next`

Метод рассчитывает сумму ежемесячного платежа по аннуитетной формуле, начисляет проценты по ставке договора и при просрочке свыше 90 дней переводит кредит в категорию проблемной задолженности с формированием резерва.

## 4. Обработка списания

- В день списания Банк создаёт попытку списания на сумму ближайшего платежа.
- Если карта доступна и средств достаточно, Банк списывает сумму платежа и уменьшает остаток задолженности по кредиту.
- Результат попытки фиксируется в истории списаний и доступен через метод 3.6.
- В случае неуспешного списания Банк повторяет попытку столько раз, сколько потребуется до погашения платежа.

## 5. Коды ошибок

Тело ответа с ошибкой имеет вид `{"code": "...", "message": "..."}`.

| HTTP | Код | Описание |
|------|-----|----------|
| 400 | VALIDATION_ERROR | Некорректные параметры запроса |
| 401 | UNAUTHORIZED | Отсутствует или недействителен токен доступа |
| 403 | CARD_OWNER_MISMATCH | Карта не принадлежит заёмщику |
| 404 | LOAN_NOT_FOUND | Кредитный договор не найден |
| 409 | AUTOPAY_ALREADY_EXISTS | Правило автоплатежа по кредиту уже существует |
| 422 | CONSENT_INVALID | Согласие клиента отсутствует или недействительно |
| 429 | TOO_MANY_REQUESTS | Превышено допустимое число запросов |
| 503 | SERVICE_UNAVAILABLE | Сервис временно недоступен |

При ответе `429 Too Many Requests` заголовок `Retry-After` содержит количество миллисекунд до следующей допустимой попытки.

## 6. Нефункциональные требования

- Сервис должен отвечать быстро и быть высоко доступным, а количество запросов от одного клиента ограничивается разумным пределом.
- Все обращения к API должны выполняться только по протоколу HTTPS с TLS версии 1.2 или выше.
- Журнал вызовов API должен содержать идентификатор запроса `X-Request-Id`, но не должен содержать токены карт и персональные данные.
- Согласие клиента, указанное в `consentId`, должно быть действующим на момент создания правила автоплатежа.
