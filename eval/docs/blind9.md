# Спецификация требований: Овердрафт по зарплатной карте с автоматическим погашением

## 1. Общие сведения

| Параметр | Значение |
| --- | --- |
| Код документа | SRS-OVD-2026-04 |
| Версия | 1.2 (на согласовании) |

## 2. Цели и задачи

- Предоставить держателям зарплатных карт банка краткосрочный возобновляемый кредитный лимит (овердрафт) с онлайн-оформлением в мобильном приложении.
- Автоматизировать полное и частичное погашение задолженности по овердрафту за счёт входящих зарплатных зачислений без участия клиента.
- Снизить долю просроченной задолженности (NPL 30+) по карточным кредитным продуктам за счёт приоритетного списания в день поступления заработной платы.
- Сократить время оформления продукта до 2 минут без посещения отделения банка.

## 3. Описание бизнес-процесса

1. Клиент в мобильном приложении переходит в раздел «Овердрафт по зарплатной карте» и запрашивает расчёт предварительного лимита.
2. Overdraft Service получает из АБС данные о зарплатных поступлениях за последние 6 месяцев и передаёт заявку в Скоринговый движок (CSE).
3. При положительном решении клиенту отображаются индивидуальные условия: доступный лимит, ставка, льготный период и график автопогашения.
4. Клиент выбирает желаемый размер лимита, настраивает параметры автоматического погашения и подписывает договор посредством OTP-кода.
5. Overdraft Service регистрирует договор в АБС и активирует кредитный лимит на зарплатной карте.
6. При поступлении очередного зарплатного перевода на карточный счёт модуль автопогашения формирует проводки погашения задолженности в порядке установленной очерёдности.

## 4. Функциональные требования

- **FR-01:** Продукт «Овердрафт по зарплатной карте» предоставляется физическим лицам — резидентам РК в возрасте от 21 до 65 лет включительно, имеющим активную зарплатную карту банка в валюте KZT.
- **FR-02:** Максимальный лимит овердрафта рассчитывается как 50% от среднемесячного зарплатного поступления за последние 6 календарных месяцев, но не более 1 500 000 KZT.
- **FR-03:** Минимальный одобряемый лимит овердрафта составляет 50 000 KZT при наличии не менее 3 последовательных ежемесячных зарплатных зачислений от одного работодателя.
- **FR-04:** Льготный период со ставкой 0% годовых действует в течение 30 календарных дней с даты первого фактического использования средств овердрафта; по истечении льготного периода применяется базовая ставка 24% годовых.
- **FR-05:** По инициативе клиента в мобильном приложении система позволяет увеличить действующий лимит овердрафта до 80% от среднемесячной заработной платы (но не более 2 000 000 KZT) без повторного прохождения скоринга.
- **FR-06:** Система должна оперативно направлять клиенту понятное уведомление при приближении к исчерпанию лимита овердрафта.
- **FR-07:** Проценты за пользование овердрафтом начисляются ежедневно в 00:05 по времени Астаны (UTC+5) на фактический остаток использованного лимита на конец предыдущего операционного дня по базе расчёта ACT/365.
- **FR-08:** При зачислении заработной платы на зарплатный счёт система автоматически списывает сумму задолженности в следующей очерёдности: просроченные проценты, текущие начисленные проценты, просроченный основной долг, текущий основной долг.
- **FR-09:** При полном погашении задолженности по овердрафту и начисленных процентов доступный лимит восстанавливается в режиме реального времени не позднее чем через 5 секунд после проведения проводки в АБС.
- **FR-10:** Минимальная сумма частичного автоматического погашения при поступлении заработной платы составляет 500 RUB, при этом начисление процентов и отображение остатка в выписке ведутся в тенге (KZT).
- **FR-11:** При возникновении просрочки свыше 5 календарных дней система начисляет пеню 0,1% в день, блокирует снятие наличных по карте в банкоматах и формирует сводную бухгалтерскую выгрузку для системы 1С в формате XML.
- **FR-12:** Клиент имеет право в любой момент полностью закрыть договор овердрафта в мобильном приложении при условии нулевой текущей и просроченной задолженности, включая начисленные проценты.
- **FR-13:** Каждый факт подключения, изменения лимита, списания автопогашения и закрытия овердрафта фиксируется в журнале аудита с указанием ИИН клиента, идентификатора договора, суммы, канала и метки времени в формате ISO 8601.

## 5. Нефункциональные требования

- **NFR-01:** Время отклика сервиса расчёта предварительного лимита овердрафта не должно превышать 1500 мс для 95-го перцентиля (p95) при нагрузке до 200 RPS.
- **NFR-02:** Интерфейс управления овердрафтом в мобильном приложении должен быть интуитивно понятным, современным и обеспечивать максимально быструю работу при любых нагрузках.
- **NFR-03:** Доступность сервиса управления овердрафтом и модуля автоматического погашения должна составлять не менее 99,95% в расчёте на календарный месяц без учёта плановых технологических окон.
- **NFR-04:** Все персональные данные клиентов и реквизиты счетов при передаче между микросервисами шифруются по протоколу TLS 1.3 с взаимной аутентификацией (mTLS).

## 6. Требования к данным и интеграциям

### 6.1 Требования к данным

- **DR-01:** Денежные суммы по овердрафту хранятся в базе данных в типе DECIMAL(18,2) с округлением по математическому правилу до двух знаков после запятой.
- **DR-02:** История операций по овердрафту и графики автопогашения хранятся в оперативном хранилище не менее 5 лет с даты закрытия договора.
- **DR-03:** Идентификатор клиента передаётся и хранится в виде 12-значного ИИН (строка из цифр, ведущие нули сохраняются).
- **DR-04:** Порядок архивации, маскирования и удаления персональных данных по закрытым договорам овердрафта — TBD (будет уточнено с департаментом ИБ после пилота).

### 6.2 Требования к интеграциям

- **IR-01:** Интеграция с сервисом уведомлений (Notification Hub) выполняется асинхронно через брокер сообщений Apache Kafka в топик overdraft.notifications.v1 с гарантией доставки at-least-once.
- **IR-02:** При отказе скоринговой системы сервис овердрафта возвращает вызывающей стороне бизнес-ошибку с HTTP-статусом 422 Unprocessable Entity и кодом причины отказа.
- **IR-03:** При недоступности АБС более 10 секунд запрос на активацию овердрафта прерывается по таймауту с возвратом кода ошибки ABS_TIMEOUT и записью события в систему мониторинга.

## 7. Критерии приёмки

| ID | Сценарий | Предусловия | Ожидаемый результат |
| --- | --- | --- | --- |
| AC-01 | Расчёт лимита | Средняя зарплата 600 000 KZT за 6 месяцев | Одобрен лимит 300 000 KZT |
| AC-02 | Подключение овердрафта | Клиент подтвердил OTP-код | Договор переходит в статус ACTIVE, лимит доступен на карте |
| AC-03 | Льготный период | Клиент подписал договор овердрафта | Ставка 0% годовых применяется в течение 45 календарных дней с даты подписания договора |
| AC-04 | Автоматическое погашение | Задолженность 120 000 KZT, зарплата 400 000 KZT | Списано 120 000 KZT, остаток долга 0 KZT, лимит восстановлен |
| AC-05 | Закрытие договора | Текущая и просроченная задолженность равна 0 KZT | Договор переходит в статус CLOSED, запись добавлена в аудит |

Приёмочное тестирование ограничивается базовыми позитивными сценариями из таблицы выше; проверка граничных значений и негативных кейсов вынесена за рамки приёмки.

## 9. Спецификация REST API: Подключение овердрафта

### 9.1 Общие параметры метода

- **HTTP-метод и URL:** GET /api/v1/overdraft/apply
- **Формат обмена:** application/json (кодировка UTF-8).
- **Аутентификация:** Bearer JWT (заголовок Authorization).
- **Идемпотентность:** Метод полностью идемпотентен: повторный вызов с теми же параметрами гарантированно не создаёт дубликат договора овердрафта.

### 9.2 Параметры запроса (JSON Body)

| Поле | Тип | Обязательность | Диапазон / Формат | Описание |
| --- | --- | --- | --- | --- |
| clientIin | string | Да | 12 цифр | ИИН клиента |
| accountId | integer | Да | > 0 | Идентификатор зарплатного счёта в АБС |
| requestedLimit | integer | Да | 10000..1500000 | Запрашиваемая сумма лимита в KZT |
| autoRepaymentEnabled | boolean | Да | true / false | Признак подключения автоматического погашения |
| repaymentSourceAccount | string | Да | KZ + 18 символов (IBAN) | Счёт для автопогашения; передаётся только при autoRepaymentEnabled = true |
| otpCode | string | Да | 6 цифр | Одноразовый код подтверждения подписания договора |

### 9.3 Параметры ответа (JSON Body)

| Поле | Тип | Обязательность | Описание |
| --- | --- | --- | --- |
| contractId | string (UUID) | Да | Уникальный идентификатор созданного договора овердрафта |
| accountId | string (UUID) | Да | Идентификатор зарплатного счёта, к которому привязан лимит |
| status | string | Да | Статус договора: ACTIVE, DECLINED |
| approvedLimit | number (decimal) | Нет | Одобренная сумма лимита в KZT |
| gracePeriodDays | integer | Нет | Длительность льготного периода в календарных днях |
| errorCode | string | Нет | Код бизнес-ошибки при отказе (например, SCORING_DECLINED) |

### 9.4 Коды ответов и примеры

| HTTP-код | Значение | Описание |
| --- | --- | --- |
| 200 OK | Успешно / Отказ скоринга | Договор активирован либо возвращён бизнес-отказ скоринга (errorCode: SCORING_DECLINED) |
| 400 Bad Request | Ошибка валидации | Некорректный формат входных параметров или неверный OTP-код |
| 401 Unauthorized | Не авторизован | Отсутствует или просрочен JWT-токен |
| 504 Gateway Timeout | Таймаут АБС | Превышено время ожидания ответа от АБС (ABS_TIMEOUT) |

Пример успешного ответа (200 OK):

```json
{
  "contractId": "7f3c9a12-4b8e-4e11-9d2a-61e5b4a0c319",
  "accountId": "e91a204b-7c3d-4c88-8b10-12a4f7c9e001",
  "status": "ACTIVE",
  "approvedLimit": 300000.00,
  "gracePeriodDays": 30
}
```

Пример ответа при отказе скоринга (200 OK):

```json
{
  "contractId": "00000000-0000-0000-0000-000000000000",
  "accountId": "e91a204b-7c3d-4c88-8b10-12a4f7c9e001",
  "status": "DECLINED",
  "errorCode": "SCORING_DECLINED"
}
```

Пример ошибки таймаута АБС (504 Gateway Timeout):

```json
{
  "errorCode": "ABS_TIMEOUT",
  "message": "Превышено время ожидания ответа от АБС при активации договора"
}
```

### 9.5 Внутренние правила расчёта скоринга

При получении запроса от Overdraft Service внешний Скоринговый движок (CSE) обязан выполнить запрос в Первое кредитное бюро (ПКБ) по протоколу SOAP, рассчитать итоговый балл по внутренней модели logistic_regression(income, dti, age) и сохранить промежуточные признаки клиента в таблицу БД scoring_raw_features.
