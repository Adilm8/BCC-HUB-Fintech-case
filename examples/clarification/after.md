Документ содержит критические противоречия в спецификации REST API (смешение кодов ответа, отсутствие метода чтения, несовпадение методов и типов данных), а также существенные пробелы в обработке ошибок, хранении данных и альтернативных сценариях. Начинать разработку и тестирование до внесения исправлений и интеграции ответов автора нельзя.

### Что исправить первым

1. **S-002** — В разделе «Часть B. REST API › Ответ» упоминается HTTP-статус 201, однако в перечне объявленных статусов (200, 400, 401, 403, 500) он отсутствует
2. **S-003** — Заголовок «200. Successful — Created» смешивает два разных HTTP-статуса: код 200 и формулировка «created» (соответствует коду 201), что создаёт неоднозначность ожидаемого кода ответа
3. **D-003** — Не указаны конкретные критерии проверки суммы и переключателя (например, допустимые значения enabled 0 и 1, границы суммы), что не позволяет написать полный набор тестов валидации
4. **D-004** — Не описано поведение системы при ошибке записи в хранилище настроек (исключение базы данных, таймаут): какой код ответа и текст ошибки возвращаются клиенту
5. **S-008** — Требование R-012 предписывает хранить данные транзакций и настроек, но не определяет срок хранения (TTL), политику архивации или удаления исторических данных за прошлые месяцы
6. **S-007** — Sequence-диаграмма и интеграционные требования описывают успешный сценарий передачи push, но не определяют поведение при сбое или таймауте сервиса push-уведомлений
7. **S-005** — В требованиях не определено, учитываются ли операции и отправляются ли push-уведомления для карт со статусами «заблокирована», «закрыта» или «истек срок действия»

### Проверка цитат и отсев находок

Каждая находка проходит детерминированную сверку цитат по тексту документа (нормализация, точное совпадение, затем нечёткое сопоставление с заменой на дословный фрагмент документа). Находки без подтверждённой цитаты отбрасываются.

Цитаты в итоговых нарушениях (у одного нарушения может быть несколько цитат):

- Цитаты, совпавшие с текстом дословно (`verified`): 29
- Цитаты, исправленные по тексту документа (`repaired`): 0
- Цитаты, заменённые текстом требования (`anchored`): 0

Находки (кандидаты в нарушения):

- Отброшено находок без подтверждённой цитаты: 0
- Отброшено на этапе критического пересмотра: 13
- Объединено с другими находками как дубли: 7
- Не подтверждено критиком (цитата только по тексту требования): 0

Баланс кандидатов: всего 47 (правила — 21, проверка каждого требования — 11, проверка набора — 14, сводные находки по матрице покрытия — 1) = итоговые нарушения 27 + объединённые дубли 7 + удалённые критиком 13 + неподтверждённые 0. Находки без подтверждённой цитаты (0) отброшены до попадания в кандидаты.

### Ограничения

- Выполняется только статический анализ текста спецификации без доступа к исходному коду, базам данных и внешним системам.
- Встроенные изображения, схемы и диаграммы в графическом формате не анализируются.
- Бизнес-корректность требований, приоритеты и выбор между противоречащими формулировками требуют подтверждения со стороны автора ТЗ.
- Предупреждение прогона: Доменный профиль banking выбран автоматически: основ найдено 9, вхождений 44.
- Предупреждение прогона: Проверка набора требований: gemini-3.5-flash: сервис модели перегружен или недоступен (попытка 1, 2 с от начала вызова); gemini-3.5-flash: дневная квота модели исчерпана (попытка 2, 11 с от начала вызова); переход на запасную модель gemini-3.5-flash-lite.
